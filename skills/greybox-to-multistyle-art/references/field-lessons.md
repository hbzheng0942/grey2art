# Load the lesson that matches the observed defect

Use during native assembly/review, not as an intake reading list. These are patterns distilled from historical case observations; the current asset/engine still needs its own check. A lesson is not a claim that every associated pipeline or teacher output succeeded. Reuse the method, not the example's dimensions, shader or camera settings.

| Observed symptom | Small discriminating check | Useful action / required evidence |
|---|---|---|
| Landmark exists but appears tiny; route still empty | Compare whole gameplay view with target hierarchy and reveal sequence | Restore main masses, near/mid/far layers and enclosure before small props; inspect actual entry/use/exit views |
| Bounds pass but object floats on a sloping/ornate support | Measure the real surface under its support footprint, not the owner's highest finial/AABB | Correct art anchor/contact recipe; native close-up plus world-space gap |
| Bottom-centered object reaches Y=0 but floats | Compare floor/collider surface with world origin | Anchor to measured support. Historical lantern floor was -0.025 m; this is an example, never a default |
| Repeated fitting changes size; scaled parent makes it huge | Recompute from immutable source through full owner transform; distinguish local/world space | Normalize once in declared space; include rotated/scaled-parent check |
| Larger requested width has no effect | Check achieved dimensions and which axis limits uniform fit | Repair local geometry/interface or report design conflict; a range pass does not prove target width |
| Appearance stays after owner removal or loses support state | Exercise actual collection/release/reset, not just spawn | Bind visuals to the gameplay owner/lifecycle and retain interaction continuity |
| Camera test passes but player/action is hidden | Inspect pixels during the actual interaction/state | Fix occlusion/visual envelope; technical camera bounds remain a separate result |
| Lighting edits never fix wrong/white material | Compare original native and converted material under the same light/camera | Check files, channels, color space, normals, alpha first; tune light only after import parity |
| Requested branch screenshot never arrives | Compare reached trajectory markers with requested anchors | Fix observation path/marker contract; preserve failed attempt |
| Coarse geographic data appears precise in the plan | Inspect source resolution/date and mapped vs inferred features | Retain road/terrain authority and uncertainty; decorative inference cannot become geographic fact |
| One beautiful mesh is called a finished style | Inspect whole composition and core interaction | Finish environment, functional appearance, joins, material/light and gameplay; human acceptance is separate |

Use [visual harness](visual-harness.md) for the material/capture diagnosis order and [hybrid production](hybrid-production.md) for missing composition. Record only applicable findings in the existing defect ledger. A matched numerical check does not replace pixel review; a historical screenshot does not certify current source. Continue good unaffected work while a bounded repair runs.

## Keep teaching compact

Keep task-specific images, attempts and corrections in that case's existing PROGRESS/review records. Promote only a reusable decision or recurring failure: amend the owning method or this symptom table with the smallest useful input → observation → correction example and its applicability limits. Replace contradicted guidance instead of appending another rule. Keep protocol fields in their single authoritative page; add a new document only for a distinct operation, then route it in the knowledge index and run `knowledge audit`. No separate transfer experiment is required to retain a useful lesson; untested generalization remains labeled.
